# Entry UUID

## Purpose

Define how UUIDv4 identifiers are generated by the Server and attached to each Logcat Entry before broadcasting, ensuring every entry in the stream has a stable, unique identifier.

## Requirements

### Requirement: UUID generation per entry

The Server SHALL generate a UUIDv4 for each parsed Logcat Entry before broadcasting it.

#### Scenario: Entry parsed and ready to broadcast

- **WHEN** the Server finishes parsing a complete Logcat Entry
- **THEN** the Server SHALL generate a UUIDv4 using `crypto.randomUUID()`
- **AND** the Server SHALL attach the UUID to the entry as a `uuid` field

### Requirement: UUID inclusion in broadcast message

The Server SHALL include the `uuid` field in every `"entry"` type WebSocket message.

#### Scenario: Entry broadcast

- **WHEN** the Server sends a WebSocket message of type `"entry"`
- **THEN** the message SHALL contain a `uuid` field with a valid UUIDv4 string
- **AND** the `uuid` field SHALL be unique across all broadcast entries within a single Server session

### Requirement: UUID format

The Server SHALL generate UUIDs conforming to RFC 4122 version 4.

#### Scenario: UUID validation

- **WHEN** a UUID is generated
- **THEN** it SHALL match the pattern `xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx` where `x` is any hex digit and `y` is one of `8`, `9`, `a`, or `b`
- **AND** it SHALL be generated using a cryptographically secure random number generator
